# Footer 수평 정렬

2026-10-29 · FooterWordmark.tsx 및 Footer.css만 변경했습니다. 기존 색상·서체·정보·Header·프로젝트·영상은 변경하지 않았습니다.

원인: 기존 Footer 패딩은 이미 대칭이었습니다. 그러나 워드마크의 block 박스는 전체 폭이고 실제 텍스트는 더 짧은 상태에서 왼쪽에 붙어 있었습니다. 태블릿은 정보 영역이1:1:1.5, 모바일은2컬럼+전체폭 연락처로 되어 있었습니다.

해결: 텍스트를 별도 span의 실제 너비로 묶고, Footer 워드마크 컨테이너의 flex justify-content:center로 중앙 배치했습니다. 모든 정보에 text-align:center를 적용하지 않았습니다. 컨테이너 쿼리 단위 cqw로 Footer 내부 가용 폭을 기준으로 글자 크기를 조절합니다. 서체·굵기·자간과 상하 여백은 유지합니다. 정보 영역은 PC·태블릿·모바일 모두 repeat(3,minmax(0,1fr))로 맞췄으며, 모바일은 컬럼 사이 간격을 줄이고 긴 연락처를 줄바꿈합니다. 각 컬럼 text-align:left, 저작권·BACK TO TOP의 양끝 정렬은 유지합니다.

## 실제 브라우저 실측

DOM Range로 실제 워드마크 텍스트 너비를 측정했습니다. 여백은 Footer 내부 콘텐츠 영역을 기준으로 합니다. 숫자의 소수점 오차는 브라우저 픽셀 반올림입니다.

시작 위치: PC x38.11 /443.25 /848.41, 태블릿 x25 /268.66 /512.33, 모바일 x20 /135.66 /251.33입니다. 각각 일정 간격이며 내부 텍스트는 모두 왼쪽 정렬입니다. 모바일은 기존2열을 요청한 동일 너비3열로 변경했으므로 연락처 줄 수가 늘었습니다.

세 화면에서 문서 가로 넘침이 없고 워드마크가 내부 폭에 들어오는 것을 확인했습니다. 하단 저작권과 버튼의 가장자리는 각각 Footer 콘텐츠 왼쪽·오른쪽 경계와 일치했습니다. PC·모바일 실제 화면도 캡처했습니다. TypeScript/Vite 빌드 통과.

신뢰도: 실제 너비·패딩 .99, 칼럼·하단 정렬 .99, 반응형 시각 확인 .97. 가중40/30/30% 기준 약 .98입니다. 모든 브라우저·실물 기기를 검증한 것은 아니며 시스템 폰트 렌더링에 따른 미세한 광학적 차이는 가능합니다.
