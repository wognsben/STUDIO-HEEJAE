# STUDIO HEEJAE Page Loading Progress Bar

2026-10-29 · http://localhost:5173/ 에 반영.

## 구현

- PageLoadingProgressBar.tsx/CSS 신규. 화면 고정 top0/left0, 높이2px, 검정 #000000, z-index9999, pointer-events:none. 트랙·그림자·노랑 없음.
- 실제 로더 상태를 제공하는 createBrowserRouter/RouterProvider로 전환했습니다. 라우터는 React 트리 밖에서 한 번 생성하며 별도의 링크 클릭·popstate 리스너를 추가하지 않았습니다.
- [React Router useNavigation](https://reactrouter.com/api/hooks/useNavigation)의 실제 pending 상태 및 새 페이지가 실제로 마운트된 상태를 함께 사용합니다. 향후 route.loader나 lazy route를 추가하면 같은 컴포넌트가 처리합니다.
- 현재 HOME/WORK는 route.lazy로 실제 모듈을 로딩합니다. 기존 AnimatePresence mode=wait와 페이지 애니메이션을 PageTransition.tsx로 옮기고, 수치는 그대로 유지했습니다. 새 화면의 마운트 완료를 알리는 useLayoutEffect만 추가했습니다.
- Header·Footer·페이지 컴포넌트·GSAP 로고·영상 재생·필터·보기 전환·프로젝트 그리드는 변경하지 않았습니다.

## 표시 방식과 정확성

- 대기가90ms 이내로 끝나면 표시를 생략합니다. 이 시간은 표시 여부를 결정할 뿐 라우팅을 지연하지 않습니다.
- 실제 진행률을 알 수 없으므로 로딩 중에는 왼쪽에서 오른쪽으로 움직이는 짧은 구간으로 불확정 진행 상태를 표시합니다. role=progressbar지만 aria-valuenow는 제공하지 않으며 임의의 숫자를 실제 진행률로 표시하지 않습니다.
- 실제 라우팅 작업과 기존 종료 애니메이션 이후 새 화면 마운트가 끝나면 전체 폭100%로 확장(.14초)한 뒤 짧은 유지(.08초)와 페이드(.2초)로 사라집니다. 이 완료 애니메이션을 페이지 이동의 완료 조건으로 사용하지 않습니다.
- 백그라운드 탭의 프레임 제한으로 완료 표시가 남지 않도록, 이미 실제 작업이 끝난 경우에만700ms 정리 타이머를 둡니다. 데이터 로딩 중에는 이 타이머로 임의 완료 처리하지 않습니다.
- 연속 이동 시 기존 tween/timeline·표시 타이머를 취소하고 재사용합니다. 언마운트 시 모두 정리합니다.
- prefers-reduced-motion에서는 이동 애니메이션 대신 정적 구간을 표시하고 즉시 정리합니다. 기존 모션 감소 설정에서는 페이지 전환도 빠르므로 일반적으로90ms 이하로 생략됩니다.
- 현재 페이지의 동일 경로·쿼리 재클릭, 페이지 내 해시 이동, 외부 YouTube 링크는 불필요하게 시작하지 않습니다. 같은 페이지라도 앞으로 실제 다른 query의 loader를 기다리는 경우는 라우터 pending에 따라 동작합니다.
