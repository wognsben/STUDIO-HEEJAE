# STUDIO HEEJAE — HOME 화질 진단 및 WORK 아이콘 변경

2026-10-29 · 로컬 서버 http://localhost:5173/ 에 반영.

## 1. 화질 측정

동일한 2번 영상 `cJsCqmQyiIM`을 인앱 Chromium에서 비교했습니다. 실제 HTML video의 videoWidth/videoHeight를 읽었습니다. 원본 업로드 파일의 해상도나 고정된 최대 화질을 측정한 것은 아닙니다.

| 조건 | 관측된 디코딩 해상도 | 상태 |
|---|---|---|
| YouTube 원본 watch 페이지 직접 재생 | 1280×720 | 음소거, 재생 중 |
| HOME iframe, 화면 안 영상 2개 재생 | 640×360 | 음소거, 재생 중 |
| HOME의 다른 영상을 직접 일시중지한 뒤 1개 재생 | 640×360 | 재생 중 |
| 후속 측정 | 직접 재생 1280×720 / iframe 640×360 | 양쪽 모두 재생 중 |

테스트 뷰포트 1280×720에서 HOME의 큰 프레임 너비는 약 735.9px였습니다. 이 프레임에 가로 640px 영상을 확대 표시하므로 선명도 저하를 설명할 수 있습니다. 초기 로딩 이후 후속 표본에서도 iframe 화질이 개선되는 것은 관측하지 못했습니다. YouTube의 적응형 화질 선택이 어떤 요인을 우선했는지는 확정하지 못했습니다.

다른 영상 일시중지 후에도 해상도가 같았으므로 **동시 자동재생이 저화질의 직접 원인이라는 결론은 내리지 않았습니다.** 네트워크·캐시·YouTube 세션·표시 크기를 완전히 통제한 벤치마크는 아니며, 모든 6개 영상에 동일한 해상도를 일반화할 수도 없습니다. 검증되지 않은 성능 개선을 목적으로 HOME을 1개 영상만 재생하도록 변경하지 않았습니다. CPU·메모리·프레임 드롭의 정량 비교는 수행하지 않았습니다.

## 2. 썸네일과 플레이어 UI

수정 전에는 로컬 썸네일 opacity=1, 플레이어 opacity=1로 썸네일이 iframe 아래에 남았습니다. DOM 순서·절대 위치상 썸네일이 영상 위에 덮이는 구조는 아니었습니다. 다만 버퍼링 상태에서도 플레이어를 숨기고 썸네일을 표시하는 분기가 있어, 로딩 도중 정지 이미지로 전환되는 현상은 발생할 수 있었습니다.

적용한 개선:

- 재생 중에는 해당 로컬 썸네일 visibility=hidden. 레이아웃 크기·위치에는 영향 없음.
- 재생 성공 후 버퍼링 상태에서는 플레이어 표시를 유지해 썸네일 전환을 줄임.
- 오류·차단·화면 밖 일시중지에서는 기존 썸네일 대체 처리 유지.
- controls=0 유지, 공식 iv_load_policy=3으로 주석 기본 표시 비활성화.
- 기존 음소거·루프·화면 밖 pause·재진입 play 유지.

수정 후 브라우저에서 실제 playing 상태의 두 카드가 poster visibility=hidden, player opacity=1인 것을 확인했습니다. 1080p 강제 설정, 플레이어 확대·크롭, 제목·로고를 가리는 요소, 플레이어 내부 CSS 조작, MP4 교체는 적용하지 않았습니다. 측정된 360p 영상이 수정 후 반드시 720p/1080p로 올라간다는 보장은 없습니다.

자막: 기존 코드에는 cc_load_policy=1 또는 cc_lang_pref로 자막을 강제 노출하는 설정이 없었습니다. YouTube 기본 동작은 사용자 선호에 따릅니다. 영상 자체에 합성된 텍스트는 플레이어 자막과 달라 제거할 수 없습니다.

공식 제한:

- [YouTube 플레이어 파라미터](https://developers.google.com/youtube/player_parameters): controls=0, iv_load_policy=3은 지원됩니다. showinfo·modestbranding은 폐기됐으며 제목·채널 정보를 완전히 제거하는 해결책이 아닙니다. rel=0도 관련 동영상을 전부 없애는 설정이 아닙니다.
- [IFrame API](https://developers.google.com/youtube/iframe_api_reference): 현재 공식 API로 1080p를 강제하지 않았습니다. 재생 해상도는 브라우저에서 허용된 video 요소 속성으로 읽기만 했습니다.
- 공식 옵션으로 제목·채널·광고·브랜딩·모든 플랫폼 UI의 완전 제거를 보장할 수 없습니다. 이 요구를 완전히 해결하려면 원본 MP4 등 별도 자산과 플레이어 선택이 필요합니다. 이번에는 MP4 교체를 진행하지 않았습니다.

## 3. WORK 확정 아이콘

- 새 `GridViewIcon.tsx`의 검정 사각 도트 매트릭스. 프레임마다 4×3개의 도트가 있으며, 각 매트릭스 바깥 경계가 정확히 16:9입니다.
- 2열은 큰 프레임 2개, 4열은 작은 프레임 4개(2×2).
- 옆에 2열/4열 텍스트. 선택 배경 #ebebeb, 비선택 투명.
- 버튼 클릭·Hover에 노랑을 사용하지 않습니다. WORK 카드의 레몬 옐로 Hover는 기존대로 유지합니다.
- 버튼의 aria-label·aria-pressed와 2열/4열 동작 유지. 브라우저 computed style에서 2컬럼·4컬럼과 선택 회색을 확인했습니다.
