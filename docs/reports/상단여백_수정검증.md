# 상단 여백 수정 검증

실제 프로젝트의 CSS 3개만 수정했습니다.

- `src/styles/tokens.css`: 공통 `--page-content-offset` 정의. 639px 이하 28px, 640~831px 32px, 832px 이상 48px. 향후 상세·CONTACT도 기존 상단 패딩에 같은 변수를 적용할 수 있습니다. 미구현 페이지는 만들지 않았습니다.
- `src/styles/global.css`: HOME·WORK 기존 상단 패딩에 공통 변수 합산. 모바일 기존 패딩도 동일하게 처리.
- `src/pages/AboutPage.css`: ABOUT 기존 상단 패딩에 공통 변수 합산.

기존 선언을 교체했으며 별도 margin이나 중복 패딩 레이어는 추가하지 않았습니다. 헤더는 position:static으로 유지됩니다.

## 브라우저 computed padding-top (px)

아래는 헤더 박스 아래 페이지 컨테이너의 상단 패딩입니다. 글자 자체의 잉크 영역까지의 거리는 폰트·필터 버튼 내부 패딩만큼 다를 수 있습니다.

| 너비 | HOME 기존 → 변경 | WORK 기존 → 변경 | ABOUT 기존 → 변경 | 추가값 |
|---|---:|---:|---:|---:|
| 1440 | 17.15 → 65.15 | 6.43 → 54.43 | 21.44 → 69.44 | 48 |
| 1280 | 15.25 → 63.25 | 5.72 → 53.72 | 19.06 → 67.06 | 48 |
| 768 | 16 → 48 | 6 → 38 | 20 → 52 | 32 |
| 390 | 10 → 38 | 10 → 38 | 20 → 48 | 28 |
| 375 | 10 → 38 | 10 → 38 | 20 → 48 | 28 |

1440/1280px에서 rem의 실제 픽셀값이 다른 것은 기존 유동 루트 폰트 크기 때문입니다. 폰트 크기 정책은 수정하지 않았습니다.

## 검증 결과

- 5개 너비 × 3페이지 = 15개 조합의 변경 전후 computed style을 측정했습니다.
- 헤더 높이는 변경 전후 동일: 1440px 약129px, 1280px 약114px, 태블릿120px, 모바일100px.
- HOME 소개 문구 아래 기존 간격 동일: 각각53.6 / 47.64 / 50 / 40 / 40px.
- 모든 너비에서 문서 scrollWidth가 viewport 너비를 초과하지 않았습니다.
- HOME·WORK 카드 및 ABOUT 캐러셀의 16:9 비율 유지.
- WORK 모바일 1열과 아이콘 숨김 유지, 데스크톱4열 유지.
- 데스크톱 WORK·모바일 ABOUT 캡처를 육안 확인: 헤더와 콘텐츠 겹침 없음.
- 브라우저 최종 오류·경고 로그 없음.
- `npm run build`의 TypeScript 및 Vite 빌드 성공. 기존 500KB 번들 경고는 유지됩니다.

기능 코드·이미지·텍스트·헤더·푸터·애니메이션은 변경하지 않았습니다. 이번 변경은 CSS 상단 패딩에 한정됩니다.

검증 신뢰도: CSS 적용 0.99, 요청 너비 반응형 0.98, 시각적 여유 평가 0.90. 가중 종합 약0.97. BUCK과의 픽셀 일치 측정은 수행하지 않았으며 사용자가 제시한 추가 여백 범위를 기준으로 조정했습니다.
