04. Grid8 / CSS GRID 상세
========================================================================
[확인] Grid8 컴포넌트 정의는 'Grid.tsx'에 있으며 이름이 Grid8이라고 파일명이 Grid8.tsx인 것은 아님. import { Grid8 } from './Grid'.

[확인] Grid8 설정:
  templateColumns: 'repeat(8, minmax(0, 1fr))'
  columnGap: 4           // Chakra spacing token
  rowGap: rowSpacing==='equal' ? 4 : rowSpacing==='flush' ? 0 : isLarge ? {base:20,sm:12,md:24} : 8
  mb: isLarge ? [4,12,24] : 0
  defaultPadding=true
  flush 기본값=true
  padding: flush==='vertical' ? px:padding : flush==='horizontal' ? py:padding : flush==='both' 또는 true ? p:padding : 없음

[확인] theme.ts의 padding 토큰: { base:4, sm:5, md:6, lg:8 }
[확인] inversePadding: 각 padding값의 음수.
[확인] Chakra 기본 spacing scale 기준: spacing 4=1rem, 5=1.25rem, 6=1.5rem, 8=2rem, 12=3rem, 20=5rem, 24=6rem.
[중요] 원본 html root는 base fontSize=20px, xl에서 1.48889vw. 따라서 spacing 토큰이 rem이면 기본 CSS 16px로 환산한 고정값(16px/80px 등)을 모든 viewport에 적용하면 원본과 틀림.
[확인] 반응형 브레이크포인트: sm=40em, md=52em, lg=68em, xl=80em. 기준 root 16px일 때 대략 640/832/1088/1280px. 미디어쿼리 em 기준은 html의 동적 font-size와 무조건 동일하게 간주하지 않음.

[확인] layout.ts:
  gridColumnMap = {col1:1, col2:2, ..., col8:8}
  gridSpanMap   = {span1:1, ..., span8:8, full:8}
  layoutItemsToRows(items, {debug=false,gridSpan=8}={}):
    rows = [{items:[],count:0,previousColumn:0}]
    지정 시작 컬럼이 있는 항목은 column >= row.previousColumn이면 현 행에 추가하고 previousColumn을 (column-1)+span으로 변경.
    겹치는/되돌아가는 시작 컬럼 요청이면 새 행 생성.
    시작 컬럼이 없는 항목은 현재 previousColumn부터 span만큼 들어갈 경우 같은 행, 초과하면 새 행.
    반환은 Row 배열(items, count, previousColumn).
  getGridColumn({gridColumn,gridSpan,numColumns=8}):
    컬럼+span이 존재하면 `${column}/span ${span}` 또는 끝 초과 시 `${column}/-1`.
    컬럼만 있으면 `${column}/-1`(범위 초과면 코드상 `7/-1`).
    span만 있으면 `span ${span}`(범위 초과면 코드상 `span 8`).
    모두 없으면 `1/-1`.
  [미확인] layout.ts의 명시적 컬럼 계산은 종료 범위가 8을 넘는 항목을 무조건 새로운 행으로 보내는 완전한 collision solver는 아님. 추측으로 동작을 추가하지 말 것.

[확인] Feed GridItem: 모바일 base에서 전체 폭, sm/md에서 getGridColumn과 행의 item 개수에 따른 배치 조절.
  2개 한 행: sm은 overlap 회피 조건에 따라 첫째 3/span3 또는 span4, 둘째 span3 또는 span4.
  1개 한 행: sm은 회피 여부에 따라 3/span6 또는 span8.
  span2는 모바일에서 1/span6, 3/span6 번갈아 배치되는 분기 존재.
  md에서는 CMS gridColumn/gridSpan과 getGridColumn을 적용.
  [중요] 모바일도 무조건 반반으로 줄이는 임의 CSS를 사용하지 말고 원본 분기 참고.

06. 미디어 가로세로비·크기·정렬
========================================================================
[적용] 모든 HOME 비디오/썸네일 프레임은 16:9. 작은 프레임들끼리 일관된 크기, 큰 프레임들끼리 일관된 크기. 큰 프레임이 가로로 넓으므로 동시에 세로로도 높게 표시됨.
[적용] 카드나 미디어의 고정 px height 금지, stretch해서 동일 높이로 맞추지 않음.
CSS 구현 개념:
  .project-media { width:100%; aspect-ratio:16 / 9; overflow:hidden; }
  .project-media img, .project-media video { display:block; width:100%; height:100%; object-fit:cover; }
  .project-card { align-self:start; min-width:0; }
[주의] 이 부분은 STUDIO HEEJAE에 대한 확정 요구사항이며 BUCK의 모든 미디어가 예외 없이 강제 16:9라고 원본 코드로 확인된 것은 아님. BUCK VideoModule은 Mux 메타데이터의 aspect ratio를 읽고 gridHeight=row 같은 예외가 존재함. 클라이언트 요구는 16:9로 통일.
[적용] 스크린샷처럼 상단 기준 정렬, 크게 보이는 미디어, 큰 행 여백. 이미지 생성 결과에서 임의로 작은 이미지를 아래로 내려 시작하게 만들지 말 것.

08. HOME 비디오 처리 — VideoModule / MuxVideo / TransitionBox
========================================================================
[확인] MuxVideo: @mux/mux-player-react 사용.
  autoPlay = background || autoPlay
  loop = background
  muted = background || autoPlay
  playsInline 적용
  minResolution='1080p'
[확인] poster 우선 Sanity thumbnail; 없으면 https://image.mux.com/{playbackId}/thumbnail.jpg?time=... 방식.
[확인] 비디오 aspect는 Mux 메타에서 계산; gridHeight='row'는 채우기 / object-fit cover 관련 처리.
[확인] progress 이벤트에서 isLoaded=true; ended 때 상태/캐러셀 콜백 처리, 재생/정지 상태 연동.
[확인] 일반 비배경 영상은 VideoOverlay에 썸네일 + 흰색 원형 재생 버튼. HOME의 background video는 해당 버튼을 무조건 올려두지 않음.
[확인] TransitionBox(일부 원본 소스에서 오타 TranstionBox):
  outer MotionBox initial rgba(0,0,0,.1) → rgba(0,0,0,0), enter duration=1s, delay=.5s.
  inner MotionBox initial opacity 0 → 1, enter duration=.5s, delay=1s.
  initial='initial', animate={isLoaded?'enter':'exit'}.
