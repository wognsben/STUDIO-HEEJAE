# Codex 최종 작업 지시서
# STUDIO HEEJAE — HOME / WORK 웹사이트 구현

## 0. 작업 목표 및 최우선 원칙

스튜디오 희재(STUDIO HEEJAE)의 포트폴리오 웹사이트를 React 기반으로 구현한다.

레퍼런스는 크리에이티브 스튜디오 **BUCK(https://buck.co/)** 이다.

이번 작업의 핵심은 일반적인 포트폴리오 템플릿을 새롭게 디자인하는 것이 아니다.

**이미 분석한 BUCK의 실제 레이아웃, 컴포넌트 구조, 반응형 규칙, 카드 정렬, 애니메이션 및 인터랙션을 기준으로 HOME과 WORK를 재현하는 것이다.**

단, 로고·브랜드 컬러·프로젝트 정보·영상·이미지는 스튜디오 희재의 콘텐츠를 사용한다.

디자인의 임의 재해석을 금지한다.

### 제공 레퍼런스

다음 세 이미지가 함께 제공된다.

| 파일명 | 페이지 | 용도 |
|---|---|---|
| `메인페이지 시안.png` | HOME | 비대칭 그리드, 카드 비율, 텍스트 위치 기준 |
| `work 페이지 2열(1).png` | WORK | 2열 보기 디자인 기준 |
| `work페이지 4열(1).png` | WORK | 4열 보기 디자인 기준 |

추가로 BUCK 원본 소스를 분석해 정리한 `BUCK_HOME_WORK_소스분석_구현가이드_2026-10-29.txt` 파일을 제공한다.

**구현 전 위 자료를 모두 확인한다.**

작업 우선순위:

1. 본 지시서에 명시된 확정 요구사항
2. 제공된 3개 이미지의 시각적 구조
3. BUCK 원본 소스 분석 자료의 실제 구현 규칙
4. 반응형·접근성·성능을 위한 기술적 보완

시안 이미지에 표현된 장면과 실제 소스 동작이 다른 경우, 임의로 결론 내리지 않고 차이를 보고한다. 기능과 반응형은 확인된 소스 동작을 우선한다.

## 4. 원본 디자인 시스템

BUCK 분석 결과를 기준으로 한다.

### 브레이크포인트

| 구분 | 너비 |
|---|---|
| Base | 0px |
| SM | 640px |
| MD | 832px |
| LG | 1088px |
| XL | 1280px |

### 8컬럼 그리드

```css
.grid-8 {
  display: grid;
  grid-template-columns: repeat(8, minmax(0, 1fr));
  column-gap: var(--grid-gap);
}
```

BUCK 원본 `Grid8`의 핵심값:

- 8컬럼
- Chakra spacing 4에 해당하는 컬럼 간격
- 원본 `padding` 값: base 4 / sm 5 / md 6 / lg 8
- HOME `isLarge` 행 간격: base 20 / sm 12 / md 24

Chakra spacing 값은 그대로 px로 해석하지 않는다. 원본의 spacing scale을 확인하여 변환한다.

원본의 `html` 기본 글자 크기와 XL에서의 유동 글자 크기도 간격 계산에 영향을 주므로 고려한다.

### 타이포그래피

BUCK은 Mabry를 우선 사용하는 시스템이다.

다만 스튜디오 희재는 로고의 서체와 별개로 본문·UI 서체를 적용할 수 있다.

- UI는 가독성 높은 산세리프
- 프로젝트 제목은 검정
- 설명은 회색
- 불필요한 굵은 제목 남용 금지
- 충분한 줄간격
- 레퍼런스와 유사한 작은 메타데이터

## 5. HOME 페이지

경로: `/`

**제공 이미지: `메인페이지 시안.png`**

HOME은 WORK와 달리 비대칭 프로젝트 피드이다.

### 5-1. 핵심 레이아웃

데스크톱에서 8컬럼을 기준으로 다음과 같이 구성한다.

| 행 | 왼쪽 | 오른쪽 |
|---|---|---|
| 1행 | 작은 카드 3컬럼 | 큰 카드 5컬럼 |
| 2행 | 큰 카드 5컬럼 | 작은 카드 3컬럼 |
| 3행 | 작은 카드 3컬럼 | 큰 카드 5컬럼 |

현재 시안은 **총 6개 프로젝트, 3행**이다.

시안 검증 단계에서 이 배치를 우선 적용한다.

추후 실제 프로젝트 데이터에서는 `gridColumn`, `gridSpan`을 수정하여 다른 구성도 지원할 수 있게 만든다.

### 5-2. 미디어 프레임

**가장 중요한 필수 조건이다.**

모든 이미지·영상 프레임은 `16:9`를 유지한다.

- 작은 카드끼리 같은 너비
- 작은 카드끼리 같은 프레임 높이
- 큰 카드끼리 같은 너비
- 큰 카드끼리 같은 프레임 높이
- 작은 카드와 큰 카드의 높이는 달라야 함

고정 높이로 두 크기를 동일하게 만들지 않는다.

```css
.project-media {
  width: 100%;
  aspect-ratio: 16 / 9;
  overflow: hidden;
}

.project-media img,
.project-media video {
  display: block;
  width: 100%;
  height: 100%;
  object-fit: cover;
}
```

카드의 크기를 바꾸기 위해 16:9 비율을 깨뜨리지 않는다.

이미지 내부의 인물이나 피사체 위치는 `object-position`으로 조정할 수 있다.

### 5-3. 카드 하단 텍스트

**BUCK 원본의 카드 정보 배치를 정확하게 재현한다.**

모든 HOME 프로젝트 카드의 하단은 다음과 같은 두 영역으로 구성한다.

왼쪽:
- `Work`
- 노란색
- 카드 이미지의 왼쪽 경계에서 시작

오른쪽:
- 프로젝트 제목
- 프로젝트 설명
- 모두 **왼쪽 정렬**
- 설명은 제목 바로 아래에서 시작

절대 금지:

- 제목과 설명을 `text-align: right`로 처리
- 설명을 카드 중앙에 배치
- `Work`를 이미지 가운데 배치
- 제목과 설명을 서로 다른 시작선에 배치
- 제목과 설명을 카드의 맨 오른쪽 끝으로 강제로 밀어 넣기

텍스트가 오른쪽 영역에 있다는 것과 오른쪽 정렬이라는 것은 다르다.

카드의 메타데이터도 해당 카드 너비 안에서 그리드로 구성한다.

```css
.project-meta {
  display: grid;
  grid-template-columns: 1fr 1fr;
  column-gap: 16px;
  align-items: start;
}

.project-meta__category {
  color: var(--color-yellow);
  text-align: left;
}

.project-meta__content {
  text-align: left;
}

.project-meta__description {
  color: var(--color-description);
}
```

위 코드는 구조 예시다. 실제 컬럼 배치 비율과 반응형 속성은 제공된 BUCK 소스 분석 자료 및 이미지와 대조하여 조정한다.

**카드의 미디어가 끝나는 위치 바로 아래에 해당 카드의 메타데이터가 시작되어야 한다.**

### 5-4. 프로젝트 간 여백

HOME은 WORK보다 행 사이의 여백이 크다.

- 각 프로젝트가 독립적으로 돋보이는 구조
- 이미지와 다음 행이 지나치게 붙지 않도록 처리
- 모든 행에 동일한 이미지 높이를 강제하지 않음
- 메타데이터는 다른 카드의 높이에 영향받아 아래로 밀리지 않음

원본 `Grid8 isLarge` 설정을 우선 적용한다.

### 5-5. HOME 인터랙션

- 이미지 로딩 시 페이드인
- 자체 MP4/WebM 영상은 조건에 따라 muted autoplay loop
- IntersectionObserver로 프로젝트 추가 표시
- 최초 프로젝트 4개, 이후 4개씩 추가
- 페이지 진입·종료 애니메이션
- 기본 HOME 카드에는 WORK 전용 Hover 오버레이를 적용하지 않음

단, 시안의 첫 6개 프로젝트는 레이아웃 확인이 가능해야 한다.

추후 실제 프로젝트가 늘어나더라도 동일한 컴포넌트를 사용한다.

## 6. WORK 페이지

경로: `/work`

**제공 이미지:**
- `work 페이지 2열(1).png`
- `work페이지 4열(1).png`

WORK는 HOME과 전혀 다른 그리드 구조를 사용한다.

**HOME = 비대칭 쇼케이스**

**WORK = 정돈된 포트폴리오 아카이브**

WORK에 HOME의 3:5 비대칭 레이아웃을 적용하지 않는다.

### 6-1. 전체 페이지 구조

위에서 아래로 다음 순서다.

1. 공통 Header
2. 카테고리 필터 및 그리드 전환 컨트롤
3. 프로젝트 썸네일 그리드
4. 각 썸네일 아래 프로젝트 제목
5. 추가 프로젝트 콘텐츠

카테고리 필터와 작품 그리드 사이의 여백은 제공 이미지를 기준으로 설정한다.

### 6-2. WORK 카테고리

최신 요청과 제공된 시안에 맞춰 구성한다.

`OUR WORKS`는 필터 영역의 제목으로 표시한다.

실제 필터 항목:

- 전체
- 홍보영상
- 모션그래픽
- 강연/인터뷰/스케치
- 광고/바이럴

필터는 지정된 명칭과 순서를 유지한다.

이전 지시서의 `유튜브/기타`는 현재 시안에서 빠져 있으므로 이번 단계에서는 추가하지 않는다.

카테고리 구조는 데이터로 관리하여 향후 추가 가능하게 만든다.

**필터 레이아웃:**

- 왼쪽 정렬
- BUCK처럼 텍스트 중심
- 기본 상태는 전체 프로젝트 표시
- 선택된 항목은 밑줄로 구분
- 클릭 시 화면 새로고침 없이 필터링

필터를 노란색 버튼이나 둥근 배지로 변경하지 않는다.

### 6-3. 그리드 보기 전환

카테고리 필터와 같은 컨트롤 영역의 오른쪽에 아이콘 두 개를 배치한다.

- 2열 보기
- 4열 보기

BUCK 원본처럼 선택된 보기 방식에 배경 또는 명확한 활성 상태를 적용한다.

실제 클릭 가능한 버튼이어야 한다.

보기 전환 시:

- 동일한 프로젝트 데이터 유지
- 컬럼 수만 변경
- 페이지 새로고침 없음
- 필터 선택 상태 유지
- 레이아웃 전환 시 콘텐츠 깨짐 없음

### 6-4. WORK 2열 보기

**기준 이미지: `work 페이지 2열(1).png`**

- 프로젝트 카드 2개씩 한 행
- 모든 카드가 같은 너비
- 모든 썸네일은 16:9
- 썸네일 바로 아래 작품명
- 카드 간 간격 일정
- HOME보다 정돈된 느낌
- 과도한 여백이나 임의의 비대칭 금지

프로젝트 제목은 기본적으로 왼쪽 정렬이다.

시안에 없는 별도 카드 테두리, 설명 카드, 장식 요소는 추가하지 않는다.

### 6-5. WORK 4열 보기

**기준 이미지: `work페이지 4열(1).png`**

- 프로젝트 카드 4개씩 한 행
- 모든 카드가 같은 너비
- 모든 썸네일은 16:9
- 썸네일 바로 아래 작품명
- 2열 보기와 동일한 카드 데이터 사용
- 프로젝트 제목은 왼쪽 정렬

4열에서 카드가 작아졌다는 이유로 비율을 임의로 변경하지 않는다.

### 6-6. WORK Hover 인터랙션

BUCK 원본 `WorkIndex`와 `FeedItemProject` 분석을 기준으로 한다.

데스크톱에서 프로젝트 카드에 마우스를 올리면:

- 이미지 위에 오버레이 표시
- 오버레이 opacity 0 → 1
- 약 0.2초 transition
- 텍스트가 아래에서 위로 이동하며 나타남
- 원본의 `translateY(-15%) → 0` 등 확인된 Motion 규칙 반영
- 프로젝트 제목 및 필요한 메타데이터 표시

Hover가 종료되면 원래 이미지로 자연스럽게 돌아간다.

HOME 카드에는 동일한 WORK 오버레이를 무조건 적용하지 않는다.

모바일은 Hover가 없으므로 작품 제목을 항상 확인할 수 있게 한다.

## 7. 콘텐츠 및 프로젝트 데이터

실제 작품 영상과 이미지, 최종 링크는 후속 단계에서 제공한다.

현재는 레이아웃 검증용 콘텐츠를 사용한다.

예시 데이터:

```ts
type Project = {
  id: string;
  slug: string;
  title: string;
  category: string;
  description?: string;
  thumbnail: string;
  videoUrl?: string;
  videoType?: "youtube" | "mp4" | "webm";
  featured: boolean;
  homeOrder?: number;
  gridColumn?: string;
  gridSpan?: string;
  detailUrl?: string;
};
```

HOME과 WORK는 동일한 원본 프로젝트 데이터를 공유한다.

그러나 화면별로 표시하는 정보와 레이아웃은 달라야 한다.

- HOME: 이미지·영상 + Work + 제목 + 설명
- WORK: 이미지·영상 + 작품명, 데스크톱 Hover 정보

임시 프로젝트는 실제 클라이언트의 실적으로 오인되지 않도록 관리한다.

레퍼런스 이미지를 재사용할 수 있더라도 최종 공개 사이트에서는 적법하게 사용 가능한 클라이언트 자산으로 교체한다.

---

## 8. 영상 처리

클라이언트의 영상 작업물은 YouTube 콘텐츠가 중심이다.

기본 구현 방식:

- YouTube ID 추출
- 썸네일 우선 표시
- iframe 지연 로딩
- 필요할 때만 플레이어 생성
- 직접 업로드한 MP4/WebM 재생 지원
- 자체 영상 자동재생 시 muted, loop, playsInline 사용
- 영상 로딩 실패 시 썸네일로 대체

BUCK의 Mux 영상과 YouTube 영상은 동작 방식이 다르다.

유튜브 자동재생, 반복, UI 숨김 등은 실제 브라우저와 플레이어 제약을 검증한다.

**영상 재생 방식 때문에 16:9 프로젝트 프레임의 크기나 배치가 변경되어서는 안 된다.**

## 9. 공통 애니메이션

BUCK `Layout.tsx`에서 확인한 설정을 기준으로 한다.

페이지 진입:

```ts
initial: { y: 15, opacity: 0 }

enter: {
  y: 0,
  opacity: 1,
  transition: {
    duration: 0.45,
    ease: [0.29, 0.01, 0.14, 1]
  }
}
```

페이지 종료:

```ts
exit: {
  opacity: 0,
  transition: {
    duration: 0.4,
    ease: [0.91, 0.01, 0.67, 1]
  }
}
```

헤더 진입은 원본과 같이 지연된 페이드인을 적용한다.

애니메이션을 과장하거나 새로운 연출을 임의로 추가하지 않는다.

사용자가 모션 감소를 설정한 경우 이를 존중한다.

## 11. 구현 범위

이번에 실제 구현할 페이지:

- `/` — HOME
- `/work` — WORK

이번에 구현하지 않을 페이지:

- ABOUT
- CONTACT
- 서비스 소개
- 프로젝트 상세페이지
- CMS 관리자 페이지

향후 확장 가능한 구조만 준비한다.

아직 구현하지 않은 메뉴는 비활성 상태임을 구분하거나 적절한 임시 처리만 수행한다.

작업 범위를 벗어나는 페이지를 임의로 생성하지 않는다.

### 가장 중요한 최종 지시

**BUCK을 참고하여 새로운 디자인을 만드는 것이 아니라, 제공된 HOME·WORK 시안의 구조와 기존 BUCK 소스 분석 결과를 기준으로 정확하게 구현한다.**

새로운 디자인 요소, 프로젝트 섹션, 그리드 방식, 카드 스타일을 임의로 추가하지 않는다.

**HOME은 비대칭 쇼케이스, WORK는 2열·4열로 전환하는 정돈된 포트폴리오 아카이브다.**

두 페이지는 동일한 브랜드 시스템을 공유하지만, 프로젝트 그리드와 카드 메타데이터 표현 방식은 각각 다르게 구현한다.
